# 交付、审查与试片修订

## 先形成执行事实，再组织语言

在内部厘清以下事项，成品不必机械保留所有标题：

| 检查项 | 需要确定的事实 |
|---|---|
| 片段任务 | 本段发生的事件、观众新增的信息、结束悬念或结果 |
| 输入条件 | 片长、画幅、风格、真实参考图、音频需求、已知模型条件 |
| 入场状态 | 谁在哪里、在做什么、看哪里、持有什么、哪些前情已发生 |
| 过程 | 可观察的动作与台词，触发、接触或阻力，动作的结果 |
| 摄影 | 观众从哪一侧、何种景别看到什么；运动或切换为何必要 |
| 声音 | 谁说什么，声音从哪里来，如何与画面事件同步 |
| 出口状态 | 人、物、环境的确切变化，下一段须继承什么 |
| 边界 | 不能提前出现的剧情；本次已出现或很容易出现的生成偏差 |

不足以确定关键人物、剧情或必要参考素材时先问。普通试片无需强制创建全套资产。

## 时间预算

- 时间段覆盖请求时长，没有无人说明的空白、重叠或越界；时间窗是执行规划，不保证模型逐帧准确。
- 对白以自然朗读估时，考虑停顿、吸气和听者反应，不只用固定字数阈值判断。
- 区分可以并行的行为（走路与说话）和必须串行的动作（接稳杯子后松手）。
- 极远景转脸部近景需要可理解的摄影方案；不要让摄影机在极短时间跨越巨大距离而仍被要求自然平稳。
- 末尾按叙事需要留下可辨认结果，但不固定每段必须留一秒、不强行定格。
- 用户要求超载时，说清哪组动作来不及，给出拆段或缩减的选择，不暗自更改主要事件。

## 最终输出形态

1. 代码块外列出需要上传的实际参考图及顺序。缺失或不支持的资源另行说明，不能把它写成已经存在。
2. 每段一个完整代码块，正文依次交代生成条件、参考职责、场景和入口、时间过程、声音及出口约束。段落可以合并，但信息不可缺失。
3. 一个片段中多镜头仍在一个块里；多生成片段各自独立完整。重复必要身份和环境不是冗余，用户不应自行组合。
4. 对简单改动也提供完整替换稿，除非用户明确只要改动部分。不要把解释、待选方案或多个“或”混进最终执行块。

可选标题用中文，例如“参考图职责”“起始状态”“0—4秒”“结束状态”。模型名、图号、资产名可保留原始写法；没有实际绑定的英文协议字段不增加可执行性。

## 出稿检查

- **事实：** 未改剧情、人物动机或关系；最新服装要求优先于旧资料；未暗示未获确认的身份。
- **参考：** 引用全部真实且角色分工清楚；未把参考图排版当成视频内容；光线或服饰覆盖规则不矛盾。
- **动作：** 看见目标后才反应；前置动作没有省略；力或接触存在时有后果；道具不无故消失。
- **表演：** 微表情有具体部位和变化；需要终止的笑与凝视有退出条件；没有末句又补回“余韵”等抽象要求。
- **镜头：** 景别看得见目标细节；方向衔接成立；切镜带来新信息或必要视角；声音和动作不因切镜重置。
- **时间：** 所有动作放得下；台词可自然说完；不是为了填时长添加无关事件。
- **交付：** 每段完整可复制；缺项不装作已具备；没有把指定模型未确认的能力当保证。

## 反馈修订

采用“现象—可能原因—修改—复测”记录，而非直接下模型能力结论。

示例：
- 现象：用户报告女主一直微笑，像在等男主。
- 可能原因：提示词要求她目送并保持笑意，且未定义相遇前的视线。
- 修改：碰面前看行进路线；笑容绑定一句台词，说完嘴角放松；走开后才回头。
- 复测：只有用户再次试片或实际看片后才记录效果。文本合规不能替代视频验证。

一次改动优先针对已观察问题，保留已有效的角色、场景和节奏；若空间逻辑本身冲突则整体修复，并解释影响。反复失败时考虑关键帧、较少同时运动的主体或重新拆段，不先一概删掉精细表演。
